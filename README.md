# cc-baggage-routing

联程行李、航段和交接事件管理服务。

## 主要业务规则

1. **行李登记**：行李以唯一标签（tag）登记，记录旅客行程和按顺序排列的航段（初始路线）。
   航段链必须从行李初始地点出发且首尾相接，否则拒绝登记。
2. **单一位置不变式**：行李在任一时刻只能处于一个明确地点（`locationCode`）
   或一个运输航段上（`currentSegmentId`），二者必居其一。位置只能通过事件流转，
   任何接口都不允许直接覆盖当前位置。
3. **事件不可变**：每次装载（LOAD）、卸载（UNLOAD）、交接（HANDOVER）都会形成
   不可修改、不可删除的事件记录。装载必须匹配当前生效路线中顺序最前的计划航段
   （航班号、起点一致）；卸载地点必须与航段终点一致，在计划外地点发现行李必须走误装流程。
4. **改签重建路线**：旅客改签确认后，在同一事务内一次性取消旧路线的全部未执行
   （PLANNED）航段并创建新的替代路线；已装载/已完成的航段、既有事件与交接记录
   一律不得改变。新路线必须从行李当前位置（在航段上时为该航段终点）接续。
5. **幂等与并发**：
   - 改签业务号（changeNo）全局唯一：同一业务号重复确认且航段内容一致时返回首次
     创建的路线，内容不一致返回 409 冲突。
   - 外部事件号（externalEventRef）全局唯一：重复扫描同一外部事件返回首次结果，
     事件内容变化返回 409 冲突。
   - 所有写操作对行李行加悲观锁，并发装载与改签同一行李时被串行化，只会形成
     “原航段装载成功”或“新路线生效”其中一种一致结果，行李绝不会同时出现在两条路线上。
6. **误装处理**：发现行李误装时必须登记异常卸载（EXCEPTION_UNLOAD，不可变事件）
   并挂接新的接续计划路线（MISLOAD_RECOVERY），禁止直接覆盖当前位置。误装航段作为
   事实保留为 LOADED。多次异常按发生顺序形成处理链（记录前一异常 id）。
   EXCEPTION_UNLOAD 不允许作为普通事件直接上报。
7. **查询能力**：提供行李当前状态、当前计划路线、全部路线历史、实际事件流和
   异常处理链查询。

## API 概览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/baggage` | 登记行李（唯一标签 + 初始航段链） |
| POST | `/api/baggage/{tag}/events` | 记录装载/卸载/交接事件（幂等） |
| POST | `/api/baggage/{tag}/rebooking` | 确认改签（业务号幂等，原子重建路线） |
| POST | `/api/baggage/{tag}/misload` | 误装上报（异常卸载 + 接续计划） |
| GET | `/api/baggage/{tag}` | 行李当前状态 |
| GET | `/api/baggage/{tag}/route` | 当前生效的计划路线 |
| GET | `/api/baggage/{tag}/routes` | 全部路线历史（含已取消） |
| GET | `/api/baggage/{tag}/events` | 实际事件流 |
| GET | `/api/baggage/{tag}/exceptions` | 异常处理链 |

错误语义：404 资源不存在；409 幂等冲突（事件号/业务号内容不一致）；422 业务规则
校验失败；400 请求参数校验失败。

## 开发环境

- JDK 21
- Maven Wrapper 3.9.9
- Spring Boot 4.1.1

迁移项目沿用现有 Spring Boot 版本，其他项目使用上述版本。
